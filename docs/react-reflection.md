# React Reflection

In Phases 5 and 6, the attendance register is updated imperatively. `reports.js` requests visit data, creates table rows and cells with `document.createElement`, assigns safe text with `textContent`, then replaces the table body. The chart is updated separately with `chart.update()`. This works for a focused report screen, but the code must manually coordinate request results, table contents, filter state and chart state. In the directory, React renders the interface from state. A patient response is stored once, and the filtered list and result count are derived during rendering. Changing the search text or species filter updates the table immediately without another API request. The component structure also separates search controls, table rows and visit history, making each part easier to understand and change.

`PatientDirectory` owns `patients`, `loading`, `error`, `query`, `speciesFilter` and `selectedPatientId`. The patient list and request status belong there because they describe the whole page. Search and species values also belong there because they determine both the result count and rows. Selection is shared: it highlights the matching row and tells `VisitHistory` which record to request. `SearchBar`, `PatientTable` and `PatientRow` receive values and callbacks through props rather than maintaining duplicate state. `VisitHistory` owns its own `visits`, `loading` and `error` state because these values exist only for the currently selected patient. Its effect depends on the patient ID and cancels updates from an earlier request when selection changes, preventing stale history from appearing under a different pet.

One issue found during implementation was that the original directory response had no visit count or last-visit date, and no patient-specific history endpoint existed. The React table could not reliably display those values from its existing patient fetch. I checked the route response and database relationship, then added a grouped patient query and a history endpoint ordered by date and time. Automated tests verify counts, missing-patient status and newest-first history; browser checks confirm the list, filters and selection use the returned data. This debug process made the division clear: the server supplies authoritative relationships, while React handles local presentation state.
