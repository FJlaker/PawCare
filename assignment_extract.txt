INTRODUCTION 
In SS1 you started building a website which we are now calling “PawCare” in this assessment,  that 
helps a local pet clinic replace its paper attendance register. You created the static patient and 
report pages (Phase 1) and added a Chart.js chart with random test data (Phase 2)  using Java 
Script . 
The clinic has reviewed your prototype and now wants a working system. Staff must be able to 
register patients and record visits on any device, the attendance register and chart must show real 
data, and all records must be stored centrally so that every st aff member sees the same 
information. 
In SS2 you will continue with the same project through Phases 3 to 7. You will turn the prototype 
into a full-stack web application using Bootstrap, JavaScript, client-side storage, a Flask REST API 
with an SQLite database, and React. By the end of SS2 the  application will have the following 
pages: 
Add Patient (index.html) 
- Captures and validates pet and owner details, and saves them. 
- Button or link to navigate to Attendance Reports. 
Record Visit (visits.html) – new 
- Captures a patient’s attendance: patient, visit date, visit type and notes. 
Attendance Reports (reports.html) 
- Displays the patients who attended the clinic in the selected period, using real data.  
- Uses Chart.js to show the number of visits per month in the selected period. 
Patient Directory (directory.html) – new 
- A React page for searching patients and viewing each patient’s visit history.

(for example, full-width buttons or a shorter chart).

Phase 4 (JavaScript interactivity and validation) (15 marks) 
 
INSTRUCTIONS 
Start from a copy of your Phase 3 files. Zip all files into WST262_S2_26_SS2_Ph4_<surname>.zip. Add 
the following files: 
- js/validation.js – the validation rules 
- js/patient-form.js – event handling for index.html 
- js/visit-form.js – event handling for visits.html 
- docs/ – debugging screenshots (see instruction 8) 
 
1. Place all JavaScript in external files, linked at the end of <body> (or with defer). Do not use 
inline event attributes such as onclick or onsubmit; use addEventListener instead. 
2. In validation.js, write one function per field rule (or an object of rule functions) that returns 
an error message, or an empty string when the value is valid. Implement every patient and 
visit rule in the PawCare (Website) data requirements and use the same functions in both 
forms. 
3. index.html: when the form is submitted, prevent the default submission and validate all 
fields. Show each message below its field using Bootstrap’s is-invalid and invalid-feedback 
classes, and move the focus to the first invalid field. Also validate a field when the user 
leaves it (blur) and check it again while typing once an error is showing. 
4. When a date of birth is selected, display the pet’s age below the field, for example “Age: 3 
years, 4 months”. 
5. When the patient form is valid, create a JavaScript object for the patient, log it with 
console.log, show a Bootstrap success alert naming the pet and owner, and reset the form. 
The Cancel button must also clear all messages. 
6. visits.html: build the Patient dropdown from a JavaScript array of patient objects using the 
DOM (not options typed in the HTML). Default the visit date to today and prevent future 
dates. Show a live character counter for the notes (e.g. “42 / 200”). Validate the form on 
submit in the same way as the patient form. 
7. Use try...catch around the code that processes a valid form. Log unexpected errors with 
console.error and show a friendly message to the user. Insert any text the user typed with 
textContent, not innerHTML. 
8. In the docs folder, include a screenshot of the browser DevTools paused at a breakpoint 
inside your submit handler, and a screenshot of the Console showing a logged patient 
object.

Phase 5 (Client-side storage and dynamic reports) (20 marks) 
 
INSTRUCTIONS 
Start from a copy of your Phase 4 files. Zip all files into WST262_S2_26_SS2_Ph5_<surname>.zip. Add 
or change the following files: 
- js/storage.js – functions that read and write data in localStorage 
- js/seed-data.js – sample data 
- js/cookies.js – functions to set and read cookies 
- js/reports.js – replaces js/chart.js 
- docs/storage-analysis.pdf (or .md) – written analysis (instruction 9) 
 
1. In storage.js, write functions that store patients and visits as JSON arrays in localStorage, 
for example getPatients(), addPatient(), getVisits(start, end), addVisit() and 
getMonthlySummary(start, end). Use JSON.stringify and JSON.parse, and use try...catch so 
that corrupted stored data does not crash the pages. 
2. In seed-data.js, create sample data that is loaded into localStorage only the first time the 
application runs: at least 6 patients and at least 30 visits spread over at least 6 months. 
3. The patient form must save new patients with a unique id and must reject duplicates (see 
the data requirements) with a warning alert. 
4. The Patient dropdown on visits.html must now be built from the stored patients, and each 
saved visit must store the patient id and the staff member’s name. 
5. Allow staff to enter their name (e.g. a navbar button that opens a small form or modal). 
Store it in a cookie named staffName that expires after 30 days, with path=/ and 
SameSite=Lax. Show the name on every page, and do not allow a visit to be saved until a 
name has been set. 
6. reports.html: build the table rows with the DOM from the stored visits in the selected 
period, newest first, showing the date, “pet name – species”, owner and a visit-type badge. 
Show a summary such as “26 visits between 2026/06/01 and 2026/08/31”. “View All” must 
clear the filter. If the start date is after the end date, show a message and do not update 
the report. 
7. Replace the random chart data: the chart must show the number of visits per month in the 
selected period, including months with no visits. When the dates change, update the 
existing chart with chart.update() instead of creating a new chart. 
8. Use sessionStorage to remember the last selected start and end dates, so that the filter is 
restored when the page is reloaded in the same browser tab. 
9. Storage analysis (300–400 words): compare cookies, localStorage and sessionStorage in 
terms of capacity, lifetime, scope and whether the data is sent to the server, and justify 
where you used each one in PawCare. Then evaluate why localStorage is not appropriate 
for storing patient and owner records in a real clinic, giving at least three reasons. 
Reference your sources using the STADIO Referencing Guide.
